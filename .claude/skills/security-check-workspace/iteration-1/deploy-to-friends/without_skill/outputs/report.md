# Streamlit Community Cloud 公開前のセキュリティチェック

コード全体（`app.py`、`core/`、`tools/`、`.gitignore`、`.streamlit/config.toml`）を確認しました。コードは変更していません。

## 結論

**今のまま公開するのはおすすめしません。** 一番の問題はコードのバグではなく、アプリの作り方そのものにあります。「APIキーを secrets に入れる」ことと「ログイン機能がない」ことが重なると、**URL を知っている人なら誰でも、あなたのキーで Gemini を使い放題**になります。下の「必須」2点を済ませれば、友達数人で使う分には十分安全です。

---

## 🔴 必須（公開前に対応）

### 1. アプリを使える人を制限する
今のコードには認証がありません。secrets にキーを入れると、サイドバーには「読み込み済み」と出るだけで、アクセスした人は誰でもそのキーで生成できます。URL は LINE の転送やスクショ、ブラウザ履歴から広がることがあります。

対策は次のどちらか（両方なら確実）。
- **Community Cloud の公開範囲を private にして、友達をメールアドレスで招待する**（アプリの Settings → Sharing → "Only specific people can view this app"）。コードを変える必要がなく、一番手軽です。
- **アプリにパスワードをかける**。`app.py` の先頭あたりで、secrets に入れた共有パスワードと照合してから処理を続けます。
  ```python
  import hmac
  def check_password() -> bool:
      if st.session_state.get("auth_ok"):
          return True
      pw = st.text_input("パスワード", type="password")
      if pw and hmac.compare_digest(pw, st.secrets["APP_PASSWORD"]):
          st.session_state["auth_ok"] = True
          st.rerun()
      return False
  if not check_password():
      st.stop()
  ```
  （Google アカウントでログインさせたい場合は `st.login()` / `st.user` も使えます）

### 2. キーが漏れたり使い込まれたりしたときの被害に上限をかける
- **このアプリ専用の Google Cloud プロジェクトでキーを新しく発行する**。普段使いのキーは使い回さないでください。漏れたときにそのキーだけ無効化して作り直せます。
- **課金（Billing）を有効にしていないか確認する**。無料枠のままなら、使い込まれても最悪レート制限に引っかかるだけで済みます。課金を有効にしている場合は、Cloud Console で予算アラートを必ず設定してください。サイドバーのモデル一覧には Pro 系の高いモデルも出るので、友達が選べば料金が上がります。
- Cloud Console の「API キー」で、**このキーで呼べる API を Generative Language API だけに制限**しておく。

## 🟡 推奨（友達に使ってもらう前に知っておくこと）

### 3. 友達の入力内容のプライバシー
このアプリには、受信メールの貼り付け、PDF の要約、文章の校正など、個人的・業務的な文章が入力されやすい機能がそろっています。**Gemini API を無料枠で使うと、Google が入力と出力をサービス改善に使ったり、人が確認したりすることがあります**（有料枠では使われません）。また、全員の利用はあなたのキー（あなたのアカウント）経由で記録されます。
→ 友達には「会社の機密や他人の個人情報は入れないでね」と一言伝えておくのがおすすめです。

### 4. 利用量の上限がない
1人あたりの回数制限がないので、誰かが長文やチャットを大量に使うと、無料枠のレート制限（429）に全員が巻き込まれます。チャットは毎回会話の履歴をすべて送るので、長く続けるほど消費トークンが増えます。数人で使う分には問題になりにくいですが、気になる場合は次のような対策があります。
- 入力欄に `max_chars` を付ける
- チャットの履歴を直近 N 件に絞る
- `.streamlit/config.toml` に `[server] maxUploadSize = 10` を追加して、アップロードの上限を下げる（デフォルトは 200MB）

### 5. GitHub に上げるときに `.env` を含めない
`.gitignore` には `.env` と `.streamlit/secrets.toml` がきちんと入っています 👍。ただし次の点に注意してください。
- **GitHub のブラウザ画面でフォルダごとドラッグ＆ドロップすると `.gitignore` は無視されます**。必ず `git` コマンドで push してください。
- push する前に `git status` で `.env` が含まれていないことを確認する。
- 過去に一度でも `.env` をコミットしたことがあるなら、履歴にキーが残っています。**キーを作り直してください**。
- リポジトリは private にしておくと安心です（Community Cloud は private リポジトリにも対応しています）。

## 🟢 問題なかった点

- **secrets の読み込み方**：コードは `os.getenv("GEMINI_API_KEY")` で読んでいます。Community Cloud では secrets の最上位のキーが環境変数にもなるので、`GEMINI_API_KEY = "..."` と書けばそのまま動きます。キーそのものが画面に表示されることもありません。
- **ユーザー同士のデータの分離**：生成履歴、チャット、入力内容はすべて `st.session_state` に入っていて、ブラウザのセッションごとに分かれています。友達同士で履歴が見えてしまうことはありません。サーバーに保存もしていません。
- **XSS**：生成結果は `st.markdown` で表示されていて、`unsafe_allow_html` は使っていないので、HTML やスクリプトを埋め込まれる心配はありません。
- **プロンプトインジェクション**：システムプロンプトに秘密の情報は入っておらず、モデルからキーに触れる手段もありません。入力でモデルの振る舞いを変えられても、実害はありません。
- **エラー表示**：API エラーの詳細（`e.message`）を画面に出していますが、google-genai はキーを URL ではなくヘッダーで送るので、エラーメッセージにキーが含まれることはまずありません。
- `gatherUsageStats = false` と `headless = true` の設定も問題ありません。

## 細かい点（任意）

- `requirements.txt` のバージョンが `>=` 指定なので、デプロイのたびに最新版が入ります。動作確認したバージョンで固定（`==`）すると、更新による予期しない不具合を防げます。
- Community Cloud のデプロイ設定（Advanced settings）で、Python のバージョンを 3.12 以上にしてください。
- secrets の設定を間違えると、サイドバーに API キーの入力欄が出ます。友達が自分のキーを入力することになりますが、キーはその人のセッション内だけで使われるので危険はありません。ただ混乱のもとになるので、デプロイ後に一度自分で表示を確認してください。

**まとめ：①公開範囲を private（招待制）にするかパスワードをかける、②このアプリ専用のキーを作って課金と予算の状態を確認する、の2つをやれば公開して大丈夫です。** パスワード機能の追加や入力文字数の制限など、コードの修正が必要ならお手伝いします。
